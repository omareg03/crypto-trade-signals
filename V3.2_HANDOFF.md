## 2. Verified v3.1 defects (fix all in v3.2)
1. **Time-reversed data (root cause).** `get_klines` rows are NEWEST-FIRST (tool description + live probe). v3.1 never sorts, so the
   signal engine, ATR (14 oldest bars), 4H trend filter, BTC regime gate and close-price fallback all ran on reversed/stale data.
   Test on 2,500 random windows: reversed vs correct signal direction agree 49.7% = coin flip. Row[0] is also the still-forming
   candle → use CLOSED bars only.
2. **No edge even with correct ordering.** 3-yr 4H backtest (32 coins, fees + slippage): v3.1 stack per-trade +0.007R (in-sample) /
   −0.007R (out-of-sample); as the real 3-position portfolio −0.062R / −0.053R.
3. `get_instruments` WORKS with a `symbol` argument (tickSize, qtyStep, minOrderQty, minNotionalValue=5). v3.1 called it without one
   (blew the 1MB SSE limit) and fell back to a hardcoded table.
4. `cancel_order` REQUIRES `symbol` → v3.1 stale-order cleanup can never succeed.
5. `bridge_state.json` sits on Render's ephemeral disk → wiped on every deploy/restart; 1R reconstruction from the SL breaks once
   the SL is at breakeven.
6. 6-timeframe scanning ≈ 400+ MCP calls per account per cycle (cycles ~22 min) → constant 429s → accounts skipped.
7. Losing-streak breaker (3 losses / 6h) is too tight for a trend system (~1/3 win rate).
8. `place_order` supports `orderLinkId` (idempotency, ≤36 chars) and `preview_order` returns initial margin — v3.1 used neither.

## 5. v3.2 spec
- **Universe:** large-cap liquid perps only (Hyro low-cap rule: coins < $100M mcap capped at 5% of initial incl. leverage).
  Drop DISCOVERY_SYMBOLS and memes. NEAR/LINK stay blacklisted.
- **Data:** `get_klines(interval="240", limit=300)` → sort ascending by timestamp → drop the forming bar (start + 4h > now).
  BTC regime from `interval="D"`, sorted, closed days only.
- **Signal (closed 4H bar):** §3 winner, N=20, k from the sim, m=4.5. Rank by (close − EMA200)/ATR. Act once per new closed bar.
- **Entry:** Market with SL attached, `preview_order` first. `orderLinkId = f"qt32{base}{bar_ts}"` (≤36 chars) → idempotent.
- **Exit:** chandelier via `set_trading_stop` on each new closed bar; only ever tighten. Entry time from
  `get_stage_metrics.positions[].createdTime`; highest high since entry from klines → no local state needed.
- **Sizing:** risk% from the sim (funded max 0.5%); qty = risk$/(entry − SL); Decimal rounding to qtyStep/tickSize from
  `get_instruments(symbol)` (cached); respect minOrderQty/minNotional; notional cap 25% of equity.
- **Funded guards:** total initial margin (preview IM + open positions IM) ≤ 80% of marginLimit ($1,000 of $1,250); CPV ≤ 2× initial.
  Funded positions so far opened at 1x, so margin ≈ notional. Setting 3x leverage per symbol in the Hyro terminal frees margin
  without changing risk (risk is set by the stop distance).
- **Budgets:** today's DD + open risk + new risk ≤ 60% of the daily limit; total loss + open risk + new risk ≤ 70% of max loss.
  Brake: close all if today's DD ≥ 85% of the daily limit.
- **Portfolio:** max 3 positions, max 2 per correlation cluster.
- **Housekeeping:** cancel non-reduceOnly limits older than 2 bars (pass `symbol`). Funded: stop new entries + log "PAYOUT READY"
  at +5% ($250). Warn when no closed trade for 25 days. Losing-streak pause: 6 losses → 24h.
- **Rate limits:** 4H only → ~25 kline calls per closed bar; scan every 10 min, act only on new bars.
